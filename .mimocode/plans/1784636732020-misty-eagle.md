# Analytics Module Migration — V1 → Digital Twin

## Overview

Migrate the V1 analytics layer so it consumes the Digital Twin's immutable `TelemetryPacket` via a new `AnalyticsInput` boundary. The old analytics assumes flat fields (`packet.speed_kmh`, `packet.rpm`, `packet.driver_id`, etc.) that no longer exist. Every analytics module must be rewritten.

## Step-by-Step Implementation

### Step 1: `analytics_input.py` — The Boundary

Create `backend/analytics/analytics_input.py`:

- Frozen dataclass with `slots=True`
- Fields: `vehicle_id`, `tick_id`, `timestamp`, plus 10 optional sensor fields (`speed_kmh`, `rpm`, `gear`, `fuel_level_percent`, `engine_load_percent`, `engine_temperature_celsius`, `battery_voltage`, `odometer_km`, `brake_pad_health_percent`, `tyre_health_percent`)
- Class method `from_packet(packet: TelemetryPacket) -> AnalyticsInput` that:
  - Iterates `packet.sensor_readings`
  - Matches by `sensor_name`
  - Extracts `.value` from `NumericSensorReading` only
  - Returns `None` for missing/invalid sensors
  - Handles duplicate sensor names (first wins)
  - Raises `ValueError` for empty `sensor_readings`

### Step 2: `analytics_events.py` — Typed Event Model

Create `backend/analytics/analytics_events.py`:

- Frozen `AnalyticsEvent` dataclass with fields: `rule_id`, `event`, `category`, `severity`, `vehicle_id`, `timestamp`, `value`, `threshold`
- `to_dict() -> dict` method for backward compat with dashboard/state_manager

### Step 3: `rule_engine.py` — 7 New Rules

Rewrite `backend/analytics/rule_engine.py`:

- Import `AnalyticsInput` and `AnalyticsEvent`
- Thresholds as class-level constants
- `evaluate(input: AnalyticsInput) -> list[AnalyticsEvent]`
- 7 rules using only available signals:

| Rule | ID | Check |
|------|----|-------|
| Overspeed | DV-R001 | `speed_kmh > 120` |
| High RPM | DV-R002 | `rpm > 5000` |
| High Engine Load | DV-R003 | `engine_load_percent > 85` |
| High Engine Temp | DV-R004 | `engine_temperature_celsius > 105` |
| Low Fuel | DV-R005 | `fuel_level_percent < 15` |
| Low Battery | DV-R006 | `battery_voltage < 11.5` |
| Excessive Idle | DV-R007 | `speed_kmh < 1 and rpm > 1000` |

- Skip rules where the relevant signal is `None` (no crash, no fake data)

### Step 4: `vehicle_health.py` — Deterministic Scoring

Rewrite `backend/analytics/vehicle_health.py`:

- `analyze(input: AnalyticsInput, events: list[AnalyticsEvent]) -> dict`
- Start at 100.0, deduct per condition:
  - engine_temp > 95 → -10 (warning), > 105 → -25 (critical)
  - engine_load > 80 → -5
  - rpm > 4500 → -5
  - battery < 12.0 → -10
  - brake_pad < 50 → -15
  - tyre < 50 → -15
- Clamp to [0, 100]
- Status: "healthy" (≥80), "warning" (≥50), "critical" (<50)
- Return structured dict with `status`, `health_score`, `health`, `factors`

### Step 5: `fuel_efficiency.py` — Unavailable

Rewrite `backend/analytics/fuel_efficiency.py`:

- `analyze(input: AnalyticsInput, rules) -> dict`
- Return `{"status": "unavailable", "reason": "instantaneous_fuel_rate_not_available", "fuel_level_percent": input.fuel_level_percent}`
- No fabrication of fuel efficiency

### Step 6: `driver_behaviour.py` — Rule-Based

Rewrite `backend/analytics/driver_behaviour.py`:

- `analyze(input: AnalyticsInput, events: list[AnalyticsEvent]) -> dict`
- Check events for overspeed, excessive_idle categories
- Return `{"status": "ok", "behavior": "normal"|"aggressive"|"idle", "indicators": [...]}`

### Step 7: `driver_ranking.py` — Vehicle-Scoped

Rewrite `backend/analytics/driver_ranking.py`:

- `__init__(self)` with penalty map and per-vehicle violation tracking
- `analyze(input: AnalyticsInput, events: list[AnalyticsEvent], current_score: int) -> dict`
- First-time violations only per vehicle (dedup by `(vehicle_id, event_type)`)
- No `driver_id` from packet — use vehicle-scoped identity
- Return `{"vehicle_id": ..., "score": ..., "grade": ...}`

### Step 8: `maintenance_queue.py` — New Signals

Rewrite `backend/analytics/maintenance_queue.py`:

- `analyze(input: AnalyticsInput, analytics_results: dict) -> list[dict]`
- Rules based on available signals:
  - engine_temp ≥ 100 → "Cooling System Inspection"
  - engine_load ≥ 85 AND rpm > 3500 → "Engine Inspection"
  - health == "critical" → "Immediate Workshop Visit"
  - brake_pad < 30 → "Brake Service"
  - tyre < 30 → "Tyre Replacement"
  - battery < 11.5 → "Battery Service"

### Step 9: `trip_performance.py` — Extension Point

Rewrite `backend/analytics/trip_performance.py`:

- `analyze(input: AnalyticsInput, rules) -> dict`
- Return `{"status": "not_initialized", "reason": "trip_identity_not_available_from_telemetry"}`

### Step 10: `fleet_trends.py` — Available Signals Only

Rewrite `backend/analytics/fleet_trends.py`:

- `__init__` with `deque(maxlen=30)` for history
- `update(inputs: dict[str, AnalyticsInput]) -> list[dict]`
- Compute fleet-wide averages of: speed, engine_temp, engine_load, battery_voltage
- Return history list with timestamps

### Step 11: `event_metadata.py` — Updated Catalog

Rewrite `backend/analytics/event_metadata.py`:

- Add new events: `low_fuel`, `low_battery`, `high_engine_temperature`
- Remove `high_fuel_consumption`, `high_coolant_temperature` (not available signals)
- Keep `enrich_event()` function

### Step 12: `engine.py` — New Orchestration

Rewrite `backend/analytics/engine.py`:

- Direct imports (no try/except for core modules)
- `process(packet: TelemetryPacket) -> dict`:
  1. `input = AnalyticsInput.from_packet(packet)`
  2. `events = self.rule_engine.evaluate(input)`
  3. Fan out to all analyzers with `input` and `events`
  4. Return structured result dict
- Remove `state_manager` dependency from engine (state integration stays separate)
- Deterministic, testable, no side effects

### Step 13: Tests

Create test files under `backend/tests/analytics/`:

**`test_analytics_input.py`**: All 10 sensors present, missing sensors, empty readings, non-numeric reading, duplicate names.

**`test_rule_engine.py`**: Normal input, each rule triggered individually, None signals skipped.

**`test_vehicle_health.py`**: Healthy, warning, critical scenarios.

**`test_fuel_efficiency.py`**: Always returns "unavailable", includes fuel_level.

**`test_analytics_engine.py`**: End-to-end with a real `TelemetryPacket` from Digital Twin.

### Step 14: Integration Verification

Run the Digital Twin simulation, feed packets through the new `AnalyticsEngine`, print representative output.

## Compatibility Decisions

1. **`event_metadata.py`**: Updated to match new event names. The `enrich_event()` function signature is preserved for `state_manager.py` compatibility.

2. **`state_manager.py`**: Not modified in this migration. It still receives `analytics_results` as dicts. The new analytics output shape is dict-compatible via `AnalyticsEvent.to_dict()`.

3. **`driver_ranking.py`**: Uses vehicle-scoped identity (no `driver_id` from packet). The ranking result dict keys match what `state_manager.py` expects (`vehicle_id`, `score`, `grade`).

4. **Fuel efficiency**: Deliberately returns "unavailable" rather than fabricating data. Architecture is ready for future fuel-rate signals.

5. **Trip performance**: Returns "not_initialized" until trip identity flows through the telemetry boundary.
