# ELM327 Adapter

## Overview

The ELM327 is an OBD-II interpreter that acts as a bridge between a computer or mobile device and a vehicle's Electronic Control Unit (ECU). It translates communication between high-level software commands and low-level vehicle communication protocols.

DriveVitals uses the ELM327 adapter to access real-time vehicle telemetry through the OBD-II port.

---

## Why DriveVitals Needs an ELM327

Computers and mobile devices cannot communicate directly with a vehicle's ECU because they use different communication protocols.

The ELM327 serves as a translator by:

- Receiving commands from the backend.
- Converting them into the appropriate vehicle communication protocol.
- Sending requests to the ECU.
- Receiving ECU responses.
- Returning the responses to the backend.

Without an ELM327 (or a similar interface), DriveVitals cannot access vehicle telemetry.

## Responsibilities of the ELM327

The ELM327 performs several important tasks:

- Detects the vehicle communication protocol.
- Sends OBD-II requests to the ECU.
- Receives hexadecimal responses.
- Handles low-level communication details.
- Provides a serial interface for software applications.

---

## Supported Communication Protocols

The ELM327 supports multiple OBD-II protocols.

| Protocol | Description |
|----------|-------------|
| ISO 15765-4 (CAN) | Modern vehicles (most common) |
| ISO 9141-2 | Older Asian and European vehicles |
| ISO 14230-4 (KWP2000) | Keyword Protocol 2000 |
| SAE J1850 PWM | Older Ford vehicles |
| SAE J1850 VPW | Older GM vehicles |

> Most modern vehicles use the **CAN Bus** protocol.

---

## AT Commands

Before requesting vehicle data, the adapter can be configured using **AT commands**.

These commands control the ELM327 itself rather than the vehicle.

| Command | Description |
|----------|-------------|
| `ATZ` | Reset the adapter |
| `ATI` | Display firmware version |
| `ATE0` | Disable command echo |
| `ATL0` | Disable linefeeds |
| `ATH1` | Enable CAN headers |
| `ATSP0` | Automatically detect protocol |

## Communication Example

The following sequence demonstrates a typical communication session.

### Step 1 – Reset the Adapter

```text
ATZ
```

### Step 2 – Disable Echo

```text
ATE0
```

### Step 3 – Request Engine RPM

```text
01 0C
```

### Step 4 – ECU Response

```text
41 0C 1A F8
```

The backend then decodes the hexadecimal response into engineering values.

- **Development:** USB or Bluetooth
- **Mobile Application:** Bluetooth

## Genuine vs Clone Adapters

Many inexpensive ELM327 adapters use cloned firmware.

Common issues include:

- Unsupported PIDs
- Slower communication
- Random disconnections
- Incorrect responses

A high-quality adapter provides better reliability and compatibility.

## Python Integration

DriveVitals communicates with the ELM327 using Python libraries such as `python-OBD`.

Example:

```python
import obd

connection = obd.OBD()

rpm = connection.query(obd.commands.RPM)

print(rpm.value)
```

The library automatically:

1. Connects to the adapter.
2. Sends the request.
3. Receives the ECU response.
4. Decodes the data.
5. Returns a human-readable value.

## Role of the ELM327 in DriveVitals

The ELM327 acts as the communication gateway between the vehicle and DriveVitals.

Its responsibilities include:

- Connecting to the vehicle.
- Detecting the communication protocol.
